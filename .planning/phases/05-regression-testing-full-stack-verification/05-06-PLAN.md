`GameSyncWorker`, `GameImageSyncWorker` and `GameHLTBSyncWorker`; there is no run endpoint for
`SteamPlaytimeSyncWorker`, and adding one would be feature work (hardening-only milestone). Every

that run's result from `GET /api/worker` — the same data the `/workers` page shows.

**Flagged assumption — "edit" in D-04.** The Angular app has no game-edit screen (no UI caller
of `PUT /api/games/{id}`). The edit step therefore drives the real API contract, authenticated with the UAT user token,
and asserts the result in the UI; adding an edit screen would violate the Visual Change Lock.

**Flagged assumption — delete button visibility.** `.delete-btn` renders only for
`source === 'Manual'`; IGDB-added games are expected to default to `Manual` (DB default, and
Phase 4 UAT deleted an IGDB-added game from the UI). If the button is absent, the step records
the finding and deletes via `DELETE /api/games/{id}`, asserting the 404 — no template change.

**Flagged assumption — dotenv precedence.** `process.loadEnvFile('.env')` is assumed not to
override variables already set in the shell, so the owner-guard check in Task 2 can inject a
wrong email. If it does override, load the file only for keys not already set.

**Canon-referral breadcrumb:** committing credentials, tokens or traces is canon secret leakage —
gitleaks pre-commit hook (Phase 02-05) and `/gsd-secure-phase`; the git-ignore gates below are the
concrete mitigation.
