# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope declaration: NO NEW VISUAL SURFACE.** Phase 5 is regression testing and verification inside a hardening-only milestone (PROJECT.md: no feature work). It adds no screens, components, routes, tokens, or styling. This contract exists to (1) lock that guarantee, and (2) record the exact existing user-facing strings that the Karma specs (D-03) and the Playwright UAT script (D-04) assert on, so tests and the UI cannot silently drift apart.

Sources: all copy below was read from the current templates/components on 2026-10-24 (not invented). Upstream: 05-CONTEXT.md (D-03, D-04, D-05, D-06, D-09), 05-RESEARCH.md (Patterns 6, 7; Pitfalls 7, 9).

| Rule | Requirement |
|------|-------------|

## Copywriting Contract

Existing strings that tests and UAT assert on. These are a freeze list: changing any of them requires updating the corresponding spec/UAT step in the same change.

### Karma specs (D-03)

| Spec target | Trigger | Asserted copy / behavior | Source |
|-------------|---------|--------------------------|--------|
| `GameListComponent.deleteGame` failure | `deleteGame` observable errors (e.g. 500 with `error: 'SqlException: secret'`) | `error === 'Could not delete game. Please try again.'` — exact string; must NOT contain the status code or any server-derived text | `game-list.component.ts:135` |
| `GameListComponent.deleteGame` start | call to `deleteGame(id)` | `error` reset to `''` before request | `game-list.component.ts:132` |
| `AuthInterceptor` | request with token | header `Authorization: Bearer <token>`; no `Authorization` header when `getToken()` is null | `auth.interceptor.ts` |
| `AuthInterceptor` | response 401 | `auth.logout()` called, error re-thrown; not called on other statuses | `auth.interceptor.ts` |
| `AuthGuard.canActivate` | `isLoggedIn()` false | returns `false`, `router.navigate(['/login'])` | `auth.guard.ts` |
| `AuthGuard.canActivate` | `isLoggedIn()` true | returns `true`, no navigation | `auth.guard.ts` |

### Playwright UAT anchors (D-04) — existing UI text

| Area | Route | Anchor text / selector basis |
|------|-------|------------------------------|
| Login (unauth landing) | `/login` | Heading `Sign in`; inputs by placeholder `Email`, `Password`; submit button `Sign in` (label becomes `Signing in...` while loading, and is disabled until both fields filled); Steam button `Sign in with Steam`; link `Create one` ("No account?") |
| Login failure | `/login` | `Invalid email or password.` (HTTP 401); `Could not connect to server.` (no usable error body) |
| Route guard | `/games` etc. unauthenticated | redirects to `/login` |
| Games list | `/games` | Heading `My Games`; add button `+ Add Game`; empty state `No games match your filters.` (with 🎮 icon). Existing behavior, unchanged this phase: this same copy also shows for a fresh account with zero games (no separate "no games yet" state exists), so UAT on the fresh test account can assert it |
| Games list load failure | `/games` | `Could not load games. Is the API running?` (`game-list.component.ts:36`) |
| Now Playing load failure | `/now-playing` | `Could not load Now Playing. Is the API running?` (`now-playing.component.ts:44`) |
| Games list delete failure | `/games` | `Could not delete game. Please try again.` |
| IGDB search (add game) | `/games` modal | search input placeholder `Search IGDB by title...` |
| Now Playing | `/now-playing` | Heading `Now Playing` |
| Journal | `/journal` | Heading `My Journal` |
| Workers | `/workers` | Heading `Workers`; per-worker button `▶ Run now` (becomes `Running...` while `status === 'Running'` or triggering); `⚡ Force Run` appears only on `GameSyncWorker` |

UAT assertion rules inherited from upstream decisions:
- Worker results are asserted from `GET /api/worker` JSON (`status`, `lastError === null`), NOT from the `/workers` timestamp text — the page shows UTC as local time (pre-existing display bug, deferred, 05-CONTEXT.md). The script must not fail on that.
- Use non-force "Run now" only; `Force Run` is not part of UAT (RESEARCH Pitfall 7).
- Only `GameSyncWorker`, `GameImageSyncWorker`, `GameHLTBSyncWorker` are triggerable from `/workers`; Steam playtime sync is verified via `WorkerStatus` row / manual (D-06), not a UI click.
- UAT data names use the `uat-<timestamp>` prefix; account is `uat-test@gameplanner.local` only (D-05). No credential strings appear in this document or any committed file.

### Steam login failure path (D-09) — existing, no change required

| Element | Copy / behavior | Source |
|---------|-----------------|--------|
| Backend redirect on failed/invalid Steam callback | `302` to `{App:FrontendUrl}/login?error=steam_failed` | `AuthController.cs:65` |
| Login page handling | any `?error=` query param sets `error = 'Steam login failed. Please try again.'`, rendered in `<p class="error-msg">` | `login.component.ts` (`ngOnInit`) |
| Code exchange failure (`?code=` invalid/expired) | same copy: `Steam login failed. Please try again.`; `loading` reset to false | `login.component.ts` |

The existing login page already handles the `steam_failed` redirect, so the D-09 callback fixes (return_to check, graceful 302 instead of 500 on Steam/HTTP failure) need NO frontend change. Any D-09 test of this path asserts the `Location` header ends with `/login?error=steam_failed`; a UAT/browser check, if desired, asserts the visible text `Steam login failed. Please try again.` after navigating to `/login?error=steam_failed`.
