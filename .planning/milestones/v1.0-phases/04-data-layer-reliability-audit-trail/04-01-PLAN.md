<objective>
Prove, end to end on one write path, that a game update is both atomic and audited: the
Dapper stored-procedure call and the EF junction-table write commit or roll back together,
and the timestamp that records the change is produced in T-SQL rather than in C#.

Purpose: the shared EF/Dapper transaction is the one genuinely new mechanism in this phase
— `.planning/phases/04-data-layer-reliability-audit-trail/04-PATTERNS.md` records **no
existing example of it anywhere in this codebase**. Every other task in Phase 4 is an
application of a pattern that already ships here. Proving the transaction on a single
method, against a real SQL Server, with a real injected failure, is what makes the rest of
the phase mechanical rather than speculative.

Output: migration `36`, the audit properties on `Game`/`NowPlayingGame`, the three
transaction-shared write paths in `GameManager`, and a minimal xUnit harness whose first
test forces a failure mid-write and proves the stored-procedure row came back.
</objective>
