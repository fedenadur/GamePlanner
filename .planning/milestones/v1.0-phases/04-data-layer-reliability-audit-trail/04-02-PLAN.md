<objective>
Stop `SteamTokenStore` from growing without bound by sweeping expired entries on a schedule,
and make that sweep visible in the same place every other background task in this app already
reports.

Purpose: `SteamTokenStore` is a process-lifetime `ConcurrentDictionary` whose only removal
path is a successful redeem. Every Steam login that is started and abandoned leaves an entry
behind forever. The fix itself is small; the design decision worth honouring is D-12 — even
though a pure in-memory sweep has no external call and no meaningful failure mode, it still
reports to `WorkerStatus` so that every background task in this app shows up in one place.

Output: a `RemoveExpired()` sweep on the store, a `SteamTokenCleanupWorker` following the
canonical `BackgroundService` shape, its DI registration and `WorkerStatus` seed row, and an
automated test proving the store shrinks while live entries survive.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Steam OAuth callback → `SteamTokenStore` | A short-lived code and its auth payload (carrying an issued JWT) enter process memory here |
| `SteamTokenStore` → background sweep | A process-internal task mutates the same dictionary that request threads read and remove from |
| worker → `WorkerStatus` / `/workers` dashboard | Worker-run facts cross from process memory into persisted, human-visible state |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-08 | Information Disclosure | `SteamTokenCleanupWorker` logging and `WorkerStatus` | high | mitigate | Only the integer removed count ever enters a log template or the status row; the worker does not import the payload namespace and a source check asserts the payload type is never named in the file (Task 1) |
| T-04-09 | Denial of Service | unbounded `SteamTokenStore` growth | high | mitigate | A 10-minute `BackgroundService` sweep (D-12/D-13) removes every expired entry, bounding the dictionary to the count of live entries (Tasks 1-2) |
| T-04-10 | Denial of Service | sweep racing a concurrent redeem | medium | mitigate | The sweep predicate matches only entries already past `Expiry`, and both paths mutate via `ConcurrentDictionary.TryRemove`, so a live token cannot be swept out from under an in-flight redeem and no double-count occurs (Task 1, asserted by the live-entries-survive fact) |
| T-04-11 | Spoofing | the new optional `lifetime` parameter on `Store` | medium | mitigate | The parameter is optional with the five-minute default, is not plumbed through any controller, DTO or request model, and a source check asserts `AuthController` still calls `Store` with a single argument — so no request can widen its own login window |
| T-04-12 | Repudiation | quiet sweeps leave no log line | low | accept | D-13 deliberately trades a per-tick audit line for log-signal quality; `WorkerStatus.LastSuccessAt` still records every completed run, so a sweep is never invisible, only unnarrated |
| T-04-SC | Tampering | npm/pip/cargo installs | low | accept | No package-manager install occurs in this plan. The worker uses only `Microsoft.Extensions.Hosting` types already in-box in `Microsoft.NET.Sdk.Web`, and the test file adds no package to the harness plan 04-01 created |
</threat_model>
