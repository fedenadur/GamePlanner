Purpose: closes the two highest-severity information-disclosure findings in `.planning/codebase/CONCERNS.md` — credentials in URL query strings and real secrets committed to source control. This is the phase's headline goal.
Output: a tracer that proves the whole credential path end-to-end (config source → service → live provider call), plus redacted Steam error handling.
</objective>

  <action>
The Steam key stays in the query string — Steam's Web API offers no body-based auth and REQUIREMENTS.md CRED-02 accepts this (D-02). The requirement is closed by making sure a failure can never print the key-bearing URL.

Wrap the HTTP call and the JSON deserialization of each of the three methods in a `try` block. Use `catch (Exception ex)` at all three sites — orchestrator-resolved, and consistent with D-15's rationale: narrowing risks missing an exception type thrown from library internals (a deserialization failure, a timeout) that would then reach an outer generic logger carrying the URL, which is exactly what this requirement exists to prevent. Precede each generic catch with a `catch (OperationCanceledException) { throw; }` so a cancelled request is rethrown untouched instead of being logged as a Steam API failure — this mirrors the `catch (OperationCanceledException)`-before-`catch (Exception)` ordering the six `Workers/*.cs` classes already use.

In each generic catch: log at Error level using the `ILogger` overload that takes the exception object as its first argument and a constant message template with named parameters, then rethrow with a bare `throw`. Callers (`SteamImportWorker`, `SteamPlaytimeSyncManager`, `ProfileController`) must keep seeing the failure — swallowing it here would trade an information-disclosure bug for a silent-failure bug.

Message template rules, all three sites:
  - Allowed named parameters only: `{Vanity}` in `ResolveSteamIdAsync`, `{SteamId}` in `GetPlayerSummaryAsync` and `FetchOwnedGamesAsync`.
  - Never interpolate the `url` local or the `ApiKey` property into the template or its arguments.
  - Never pass the exception's own text — neither its message property nor its string form — as a template argument; the exception object goes in the first parameter slot, where the logging pipeline renders it, and nothing about it is copied into the message string.
  - Keep the existing pre-call `LogInformation` lines (`Resolving Steam vanity URL: {Vanity}`, `Fetching owned games for SteamID: {SteamId}`) unchanged — neither carries the key.

Leave the non-exception control flow as-is: `GetPlayerSummaryAsync` still returns null on a non-success status without throwing, and `FetchOwnedGamesAsync`/`ResolveSteamIdAsync` still throw their existing `InvalidOperationException` messages (which name only the vanity string or a generic condition, no key).
  </action>

| Boundary | Description |
|----------|-------------|
| GamePlanner.API → id.twitch.tv (IGDB OAuth2) | Client credentials cross an outbound network boundary; the request URL is visible to proxies, TLS-terminating middleboxes, and any access log |
