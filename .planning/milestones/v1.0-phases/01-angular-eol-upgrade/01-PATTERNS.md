## Shared Patterns

### Pattern: Sequential `ng update`, never hand-edit `package.json`
**Source:** RESEARCH.md Architecture Patterns, Pattern 1
**Apply to:** `package.json`, `package-lock.json` at every hop
```bash
ng update @angular/core@<N> @angular/cli@<N>
```
Running this is the only way the mandatory migration schematics execute (e.g. the v22 `ChangeDetectionStrategy.Default → Eager` rewrite, the v19 `PendingTasks` rename). Hand-editing version numbers in `package.json` skips these silently.

### Pattern: Decline every optional migration prompt
**Source:** CONTEXT.md D-03/D-06; RESEARCH.md Pattern 3
**Apply to:** every `ng update` invocation, hops 15/17/18/20/21 specifically
Decline: standalone-component conversion, `@if`/`@for` control-flow conversion, `use-application-builder` migration, Vitest (`karma-to-vitest`) migration. None of these are mandatory; accepting any of them would break the "pure dependency bump" framing this whole phase is built on.

### Pattern: Post-hop verification (build → test → serve → commit)
**Source:** CONTEXT.md D-04/D-05
**Apply to:** every hop, without batching
```bash
npm run build
npm test -- --watch=false
ng serve   # manual boot smoke check
git add -A && git commit -m "chore(deps): upgrade Angular <N-1> -> <N>"
```
One commit per hop (D-05), not one commit for the whole phase — preserves bisectability.
